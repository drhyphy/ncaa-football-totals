# Collection quota metadata amendment

Recorded September 9, 2026, after the first ACC pilot capture and before using the corrected collectors. This amends only the discretionary missing-quota-header stop in prospective ACC availability and weather revision collection. Original protocols, collection windows, profiles, cohorts, receipts and prior code remain preserved; earlier captures are not reprocessed or relabeled.

The first ACC pilot, frozen at commit `65f7fb377b1b938338eaf6b19aa8ebea960e698e`, recorded run `local-20260909T081630214455Z-1.json` from 08:16:30.214455 to 08:16:31.872356 UTC. All six requests returned HTTP 200. One pending report matched an official future game and passed its subsequent official context recheck, but no prices were requested: the selected-book and `/events` responses omitted quota headers, and the inherited inventory-header gate stopped before the single planned odds batch. The original manifest SHA-256 is `07e69ca80cd720c072ab878e6bfd369c944b877eee94ad431fb270252ed3b334`, retained under `model/data/runtime/availability/runs/`. Zero prices here reflect collection bookkeeping, not unavailable books or a completed availability report.

This repeats the observed header omission documented in the [movement preflight correction](MOVEMENT_QUOTA_REQUIREMENT_CORRECTION.md). Missing allowance metadata alone is no longer a reason for an explicitly opted-in collector to stop its existing bounded reads. The shared helper retains its original strict default (`require_quota_metadata=True`); corrected ACC and weather callers explicitly pass `False`. Weather collector version 3 records this amendment's hash and the operative quota policy, while retaining its existing pilot/season identities and dates.

The limits remain selected books plus one seven-day provider inventory and batches of at most ten matched events: at most **4 provider calls for ACC's 20-game cap**, or **17 provider calls for weather's 150-game cap**. Missing headers do not create retries, additional discovery, added books or a larger cohort. An actually reported allowance at or below 20 still stops further calls; an inventory allowance insufficient for the planned batches plus 20 stops before the batches. HTTP 401, 403 or 429 still stops. These rules apply both before and between odds batches.

Without current allowance headers, the remaining quota and a 20-request reserve **cannot be guaranteed**. The protection is the fixed request cap, no retries and respect for any actual reported low allowance or rejection; it is not a provider-limit exemption. Original receipt headers preserve whether allowance was known. No subscriptions, keys, account settings, prices, matching rules, weather definitions, model thresholds, outcomes or fitted models change under this amendment.

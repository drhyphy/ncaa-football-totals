# Official football availability reports: feasibility

Access date: **2026-09-09**. Bounded source audit: five search queries and three page/document opens; only primary conference publications support the findings below. No bulk acquisition, retrospective fitting, outcome/ROI search, credentials, or production changes. The existing [rich-feature reuse audit](RICH_FEATURE_REUSE_AUDIT.md) already identifies archived player availability as missing; this is a new source, not another transformation of the tested aggregate features.

**Verdict:** official availability changes are a feasible prospective information source, with incomplete conference and historical timing coverage. A ready-to-use, reliably timestamped historical QB-status panel was **not verified**. The narrow next step is an outcome-free collection preflight for one conference, retaining original report versions and contemporaneous prices. There is no demonstrated betting edge.

## Historical formats and timestamp evidence

An actual [Big Ten Week 2, 2023 PDF](https://s3.amazonaws.com/bigten.org/documents/2023/9/9/FB_Reporting_Week_2_ALL.pdf) is publicly readable without a key: 14 pages, one team report per page, matchup/week/kickoff, status headings, jersey numbers and player names. The inspected report has no position, stable player ID, publication clock time or revision sequence in its extracted text. It demonstrates surviving historical content, including nonconference opponents, **not** that a particular version was available at a specific betting decision. The [2023 index](https://bigten.org/fb/article/blt19caa3aea8cf4525/) lists weekly reports; its page-level publication/update dates are not individual report receipts.

A report's scheduled deadline, dated URL, CMS update date and a later download are different evidence. None establishes the original publication instant or guarantees that earlier versions were preserved. This audit verified no append-only official revision API, complete historical revision inventory, or independently certified historical release timestamps. Dynamic report pages require a separate bounded payload/schema preflight; “iframe” is not proof that data are inaccessible or that a stable API exists.

For prospective use, archive original bytes, source URL, actual request/receipt UTC, response headers, content hash, displayed issue time and timezone, report phase, conference policy version, game/team identity and explicit missing/error status. Keep every changed version and the last unchanged receipt. Actual first receipt is the conservative availability cutoff; the interval between the preceding receipt and first changed receipt bounds detection, not necessarily original publication. Retain any source issue time separately without substituting it for a receipt.

## Bounded prospective hypothesis

The Big Ten's September 2026 reporting change gives a concrete first collection target. Before scheduling anything, verify one report payload, its displayed issue-time semantics and name/jersey matching against an independently archived official roster. Resolve QB identity and pre-report role using only information already available at that time; these reports do not certify who starts, how many snaps someone will play, or backup quality. Carry conference-specific exemptions and season-long absences forward; distinguish an absent report from a complete report with no listed player. Keep status categories categorical: policy percentages are not empirically calibrated probabilities.

A later frozen comparison could ask whether **newly observed QB availability changes**, their age and prior role improve a contemporaneous market-plus-weather baseline's probability forecasts or predict the next scheduled total-price change. Use fresh paired quotes after the report receipt, retain pre-change quotes if actually captured, and count each game's observations as dependent. A status may already be priced before its official release; report-to-market association alone is not incremental predictive value. A morning 06:30 publication can use the previous evening's report, but cannot contain a final report released 90–120 minutes before a later kickoff. The existing four fixed UTC capture slots would observe many announcements with a lag; they cannot establish immediate post-announcement performance.

Freeze the cohort, status transitions, role definition, receipt cutoff, matched-price requirement and evaluation before collecting labels or fitting. Measure source coverage first. Public access establishes feasibility; it does not establish redistribution permission, full historical completeness or profitability.
